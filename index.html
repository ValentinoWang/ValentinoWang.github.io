LLM · STRUCTURED OUTPUT

大模型整理训练计划：模型负责理解，规则负责定案

问题
教练的计划写法五花八门：文字、Excel、拍照。直接信任模型输出，动作名会被「意译」，结果不可复现。
做法
按动作库和指标动态生成 JSON Schema 约束输出，再用 Pydantic 校验；动作名先走确定性对齐（库内名称、审核过的别名、教练自己确认过的叫法），模型只补语义匹配。对不上的标为「可补充」，不阻塞导入。
结果
同一输入得到稳定的动作归属，对齐逻辑可以单测；模型调用走 OpenAI 兼容接口，换供应商不改业务代码。
STREAMING · UX

流式输出，但校验逻辑一行不改

问题
整理一周计划要几十秒，教练只看到转圈；改成流式又怕绕过已有的结构化校验。
做法
把流式分片重新拼回非流式的响应结构，校验照旧执行；进度模块只「旁观」不完整的 JSON，告诉教练哪几天已经整理好。
结果
等待期间能看到逐日进度，正确性仍只由一条校验路径决定。
POSTGRES · JOB QUEUE

不引入消息队列的可靠后台任务

问题
计划整理、OCR、批量发布都是慢任务，进程可能中途退出，多个进程不能重复处理同一任务。
做法
任务表直接放在 PostgreSQL，用 SELECT … FOR UPDATE SKIP LOCKED 认领，加处理租约，租约过期自动回收；模型请求指数退避重试，区分可重试和不可重试错误。OCR 分两遍识别，只有模型调用并发，数据库写入串行，可从中断处续跑。
结果
少一套中间件，部署和排障简单，任务不丢也不重复。
DOMAIN MODEL

成绩「能一起查」不等于「能一起比」

问题
同一项 100 米，手计和电计、顺风和逆风混在一起算最好成绩和趋势，结论就是错的。
做法
每种测试方法声明必须已知且一致的条件；分类条件按取值分组（「未知」单独成组），风速这类连续值只作筛选属性，不进入分组键；方法版本也参与分组。
结果
最好成绩和趋势只在可比的记录之间计算，规则集中在一个模块里，有单元测试覆盖。
CONTRACT

前后端契约自动生成，字段对不上编译就失败

做法
后端导出 OpenAPI，自动生成 Dart 客户端；前端只能通过它访问数据。数据库变更全部走 Alembic 迁移。
结果
接口改名、删字段在前端编译期暴露，而不是上线后才发现。
QUALITY GATES

每个界面问题先写成会失败的门禁

做法
问题先变成 widget 测试或设计系统静态检查，确认在当前代码上失败，再修到通过。例如禁止按构建模式分支、禁止把类型名渲染成文字、禁止非常量图标，保证调试版和发布版画面一致；日期格式、术语也有专门检查。
结果
同类问题不会第二次出现；310 张截图带源码指纹，没拍到最新代码的截图无法发布。

多智能体并行研发

一个人同时带多个编程智能体，在同一个仓库里开发
  1. 任务拆分我把需求拆成可独立合并的小任务，每条写清验收标准和要过的门禁。
  2. 隔离开发每条开发线有独立的 git worktree、分支和调试服务端口，互不干扰。
  3. 门禁先行先写会失败的测试或检查，再让智能体修到通过；不许放宽门禁。
  4. 排队合并合并、发布、数据库迁移、构建四类共享资源各有一把排队锁，只做快进合并，同时推两个远端。
  5. 截图验收手机和桌面截图逐张看，问题退回对应开发线；通过后统一发布到截图画廊。

Siyao Wang · Tsinghua University

3 papers19 citationsh-index 2Google Scholar, 2026-10

摘要

研究从工业检测出发：锂电池极片缺陷分割、三频外差相位测量、基于光谱反射的薄膜厚度测量。之后转向 AI 辅助数学研究，用自研的 MathArc 系统研究 Erdős–Szekeres 问题的开放情形 ES(7)=33，得到一批带可重放证书的局部结构结果，手稿已整理成 arXiv 格式，原问题仍未解决。本科阶段的数学建模项目涉及自行车功率分配、FAST 反射面优化和传染病动力学。
